2. Цели ревью
   
1. Обеспечить высокую производительность: время выполнения каждого запроса не должно превышать 5 секунд при обработке миллионов строк.
2. Проверить корректность выборки данных (отчеты по продажам, остаткам и прогнозам), чтобы исключить финансовые потери.
3. Оценить читаемость кода для дальнейшей поддержки другими разработчиками.

3. Критерии проверки (чек-лист)

3.1. Функциональная корректность
- [ ] Все JOIN'ы корректны, отсутствуют декартовы произведения (cross join).
- [ ] Агрегатные функции (SUM, COUNT) и GROUP BY настроены верно, суммы в отчетах сходятся с эталонными значениями.

3.2. Безопасность / Надежность
- [ ] Корректно обрабатываются значения NULL (например, через COALESCE), чтобы избежать ошибок в отчетах.
- [ ] Отсутствуют жестко заданные (hardcoded) ID, которые могут сломать отчет при изменении данных.

3.3. Производительность
- [ ] Время выполнения запроса подтверждено через EXPLAIN ANALYZE и составляет < 5 секунд.
- [ ] Отсутствует конструкция SELECT * (выбираются только необходимые поля).
- [ ] Запросы используют существующие индексы (нет Full Table Scan на больших таблицах).

3.4. Читаемость и стиль
- [ ] Ключевые слова SQL написаны в верхнем регистре (SELECT, FROM, WHERE), алиасы таблиц — понятные.
- [ ] Сложные подзапросы вынесены в CTE (WITH) для улучшения читаемости.
